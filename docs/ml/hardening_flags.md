# ML Hardening Flags Reference

This document is the single source of truth for runtime hardening controls
introduced in recent ML hardening tranches.

Strict-mode flags are opt-in by default unless explicitly noted otherwise.

## Flags and Controls

| Flag | Default | Scope | Effect | Where Read | Related Signals | When to Enable |
| --- | --- | --- | --- | --- | --- | --- |
| `ENFORCE_MODEL_FEATURES` | `false` | Inference reload | Enforces model required-feature registry validation; when enabled, unknown required features fail reload instead of warn-only continuation. | `python/src/forecast/model_manager.py` (`_load_from_mlflow`) | `forecast_model_reload_failure_total{reason=*}`, diagnostics: `last_reload_status`, `last_reload_reason`, `degraded_reasons` | Enable after feature registry/model promotion flow is stable and strict reload correctness is preferred over soft degradation. |
| `STRICT_TUNING_RESUME_VALIDATION` | `false` | Training/tuning resume | Fails resume when stored Optuna invariants mismatch current requested invariants; disabled mode logs warning and continues. | `python/src/model/tuning.py` (`run_tuning_study`) | tuning logs with resume reason codes, optional MLflow tag `tuning_resume_reason` | Enable when exact reproducibility across resumed jobs is required. |
| `STRICT_SPLIT_STRATEGY_VALIDATION` | `false` | Training request validation | Rejects unsupported split strategies in strict mode; non-strict path preserves warn-only compatibility behavior. | `python/src/training/service.py` (`_apply_split_strategy_validation_policy`) | gRPC `INVALID_ARGUMENT` on strict failures, validation warnings in compatibility mode | Enable once all callers have migrated to supported split strategies. |
| `INFERENCE_BENCHMARK_ENABLED` | `true` | Inference reload benchmark | Toggles load-time benchmark execution. Disabled mode skips benchmark entirely. | `python/src/forecast/model_manager.py` (`_load_benchmark_enabled`) | diagnostics: `benchmark_last_status=skipped_disabled`; benchmark Prometheus metrics when enabled | Keep enabled in normal operation; disable only if reload latency budget is extremely constrained. |
| `INFERENCE_BENCHMARK_SAMPLE_RATE` | `1.0` | Inference reload benchmark | Probabilistic gating of per-version benchmark (`0.0`-`1.0`). | `python/src/forecast/model_manager.py` (`_load_benchmark_sample_rate`) | diagnostics: `benchmark_last_status=skipped_sampled_out|success` | Lower below `1.0` to reduce benchmark overhead in frequent-reload environments. |
| `FEATURE_COVERAGE_WARN_THRESHOLD` | `1.0` | Inference request-time guardrail | Threshold for logging/metrics/diagnostics warning when request feature coverage falls below expected required-feature coverage. Clamped to `[0.0, 1.0]`. | `python/src/forecast/services.py` (`_load_feature_coverage_warn_threshold`) | `inference_feature_coverage_ratio`, `inference_feature_coverage_below_threshold_total{bucket=*}`, diagnostics: `feature_coverage_warning_active` | Keep at `1.0` for strict full-coverage alerting; lower only when partial coverage is expected and accepted. |
| `INFERENCE_MODEL_RELOAD_SPAN_ENABLED` | `false` | Inference tracing | Enables MLflow reload lifecycle span creation and training identity correlation attributes. | `python/src/forecast/model_manager.py` (`_reload_span_context`) | span attrs: `model.reload.*`, `ml.training.run_id`, `ml.model.version`, `ml.feature.schema_hash` | Enable during operational incident analysis or reload latency investigations. |
| `DRIFT_PSI_WARN_THRESHOLD` | `0.1` | Drift monitoring | Warning threshold for PSI alert generation. | `python/src/training/detect_drift.py` (`_load_drift_thresholds`) | drift payload: per-feature `status=WARNING`, `alerts[]` | Tune upward/downward based on desired sensitivity to moderate drift. |
| `DRIFT_PSI_CRIT_THRESHOLD` | `0.25` | Drift monitoring | Critical threshold for PSI alert generation and drifted-feature marking. | `python/src/training/detect_drift.py` (`_load_drift_thresholds`) | drift payload: `drift_detected`, `drifted_features[]`, critical alerts | Tune to production tolerance for severe distribution shifts. |
| `DRIFT_PSI_MIN_EXPECTED_PER_BUCKET` | `5.0` | Drift PSI robustness | Minimum expected mass per bucket for trustworthy PSI on sufficiently large references. | `python/src/training/detect_drift.py` (`calculate_psi`) | drift metadata: `drift_error=insufficient_bucket_mass`, bucket guardrail metadata | Raise for stricter PSI quality checks on sparse baselines. |
| `DRIFT_PSI_MIN_NONEMPTY_BUCKETS_RATIO` | `0.6` | Drift PSI robustness | Minimum non-empty reference-bucket ratio for trustworthy PSI on sufficiently large references. | `python/src/training/detect_drift.py` (`calculate_psi`) | drift metadata: `drift_error=insufficient_bucket_mass`, `nonempty_buckets_ratio` | Raise when requiring stronger bucket coverage before alerting. |
| `DRIFT_REFERENCE_MODEL_ALIAS` | `\"\"` | Drift reference selection | Preferred alias used to resolve reference model for drift baselines before stage/latest fallback. | `python/src/training/detect_drift.py` (`_select_reference_model_version`) | drift payload: `reference_resolution` metadata (`resolution_strategy`, selected version/run_id) | Set in production for deterministic baseline reference selection. |
| `TUNING_MLFLOW_NESTED_RUNS` | `false` | Tuning observability | Enables nested MLflow trial runs for completed trials in tuning jobs. | `python/src/model/tuning.py` (`JobProgressCallback`) | nested MLflow runs (trial params/metrics), tuning logs | Enable only when per-trial MLflow lineage detail is needed. |

## Calibration Viability Controls (Request Fields)

These controls are not environment flags; they are request-level guardrails
passed from training RPC inputs into `train_model`.

| Flag | Default | Scope | Effect | Where Read | Related Signals | When to Enable |
| --- | --- | --- | --- | --- | --- | --- |
| `min_cal_samples` | `100` (RPC `TrainRequest` fallback), `200` (direct `train_model` default) | Training calibration | Minimum calibration sample count required to fit calibrator. Below threshold causes skip. | `python/src/training/service.py` -> `python/src/model/train.py` | MLflow params: `calibration_enabled`, `calibration_samples`, `calibration_skip_reason` | Increase when calibration stability is more important than always fitting. |
| `min_cal_pos` | `10` (RPC `TrainRequest` fallback), `5` (direct `train_model` default) | Training calibration | Minimum positive-class count in calibration slice. Below threshold causes skip. | `python/src/training/service.py` -> `python/src/model/train.py` | MLflow params: `calibration_pos_count`, `calibration_skip_reason` | Increase for high-confidence positive calibration requirements. |
| `min_cal_neg` | `10` (RPC `TrainRequest` fallback), `5` (direct `train_model` default) | Training calibration | Minimum negative-class count in calibration slice. Below threshold causes skip. | `python/src/training/service.py` -> `python/src/model/train.py` | MLflow params: `calibration_neg_count`, `calibration_skip_reason` | Increase for high-confidence negative calibration requirements. |
